# 维护与证据政策

本政策把“值得研究”与“有资格进入发布复核”分开。维护者可以在用户既有授权内调查、测试并发布合格的常规更新；不需要每次重新请求批准。但新增费用或订阅、私人材料授权不足、许可证不清、高风险或实质扩展范围时，必须停下并取得相应授权。

政策版本：`maintenance-v1`。以下数值是保守的初始操作门槛，不是经验证的普适写作标准，也不是统计功效保证。门槛、样本计划和裁判规则必须先冻结，不能根据结果调低门槛、切换指标或追加样本直至显著。调整政策须另行说明理由和版本，对未来试验生效。

## 适用时间与当前结论

本政策前瞻适用。现有功能实验版继续按已有披露分发，不追溯声称通过新门槛。具体版本、来源和结果以 [EVALUATION.md](../EVALUATION.md) 为准：需要编辑的组合对旧版为 **3 胜 / 7 平 / 1 顺序不稳定**，对直接提示为 **2 胜 / 8 平 / 1 顺序不稳定**；不是整体文风优势的证明。档案定向回归的新版本 5/5、对照 4/5，也不满足本政策未来要求的原故障加至少 12 个新保护来源、两次重复试验。

本次增加维护协议、离线评估器和单元测试，本身不改善或证明技能的写作效果。结构测试、功能检查、读者偏好、真实个人声音和真实文件状态是不同证据，不合并为一个成功率。

## 每周筛分：是否值得投入

每项按 0–2 分评分，保留具体来源和理由，满分 10。高分始终表示更值得调查；`affordability` 高分表示维护成本较低。

| 项目 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| `relevance` 相关性 | 超出支持范围 | 间接相关 | 直接影响中英文支持工作流 |
| `gap_evidence` 缺口证据 | 只有宣传或直觉 | 有可信线索 | 有可复现问题或明确缺口 |
| `portability` 可移植性 | 依赖不可用或不兼容能力 | 有受限适用范围 | 不依赖新增专属服务，边界清楚 |
| `testability` 可检验性 | 没有可观察验收条件 | 可以部分检验 | 可复现、可对照且有保护性检查 |
| `affordability` 维护负担 | 超预算或复杂度不明 | 有可管理的新负担 | 小范围、可回滚、符合预算 |

总分至少 7 且没有许可证或安全否决，才建议 `investigate`；不是发布许可。许可证、安全或公共数据授权尚未核实，先 `defer`。已确认的许可证或安全失败为 `reject`。上游热度、提示长度、禁词数量、模型自评和所谓“更像真人”的印象均不能代替证据。

## 三种发布证据层级

### 1. 文档与结构维护：`docs_structure`

只允许准确说明、链接、打包或不改变写作行为的结构修复。必须证明行为未变、结构检查通过、许可证和安全检查通过，并由非作者复核实际差异及回滚方式。不得据此声称写作质量改善。行为变化不能放进这个层级绕过测试。

### 2. 定向修复：`targeted_bugfix`

先登记具体故障、适用语言与路径、原故障复现方式、保护案例组成和验收条件，再冻结候选版本。

- 至少一个原故障来源；旧版在两次重复中均复现该故障，候选在两次重复中均通过。
- 至少 12 个不同来源的新保护单元，冻结候选前未用于调优。声明中英文时，两种语言都要覆盖；声明多个路径时，每个语言×路径单元格均须覆盖。
- 单一单元格至少 12 个保护来源；多个单元格各至少 6 个，并且总体至少 12 个不同来源。重复使用同一来源不能增加总体来源数。
- 保护案不能全部是故障变体：预注册中必须覆盖原本良好、应少改或不改的文字，以及适用文体、正式程度、作者立场、限定条件与不必要改动风险。复核者在 `stance_priorities_voice` 的证据中记录组成和实际检查结果。
- 所有案例执行两次生成；所有语义、隐私、授权和文件边界检查均通过；观察到的失败、无效结果和缺失结果均为零。

通过仅支持“在所登记条件与案例中修复了该故障”。**零观察失败不等于零风险**，不得换写为总体风格优势。保护案中的 `incumbent_reproduced` 两个布尔值只记录旧版是否出现原故障；保护案不要求旧版失败，也不拿这些值计算改善率。

### 3. 范围限定的风格改善：`style_improvement`

`general_style_advantage` 是机器字段名，仅表示预注册语言、路径、文体、任务分布与模型条件内的较广泛优势假设，不是普适优势。每个拟声明的语言×路径必须单独满足全部条件，不可用另一语言或路径的优势抵消。

预注册必须包含：新鲜保留材料的选择方式、来源级单元及固定样本量、许可、文体组成、版本与完整提示/资源哈希、模型与设置、相同任务和信息保留要求、组合路径各阶段、裁判规则、全部对照、失真判定、盲化方式和分析计划。材料不得与开发材料共享来源级单位；同一作者或文档的相关片段应在设计阶段合并/分组，不能冒充独立文本。遇到来源依赖不清，推迟结论。

对照必须同时包含当前已发布版本 `incumbent` 和不加载专用技能但任务及保留要求相同的 `plain`。匿名比较，正反展示顺序分别置于新上下文；编辑器只能获得任务、原文及其条件资源，不得获得预期问题、判分答案或条件身份。模型、设置、阶段、失败记录和调用次数均留痕。每个来源每种条件生成两次，两次生成不是两个独立来源。

裁判不得是编辑器的同模型自评。一般优势标签须有独立模型族或独立人类读者，并记录身份、与作者/编辑器的隔离及适用量表校准证据。同模型新上下文、另一个同模型 agent 或换序只能减少某些偏差，仍属探索性证据。独立 agent 可满足发布流程的产物复核，但不因此成为独立模型族验证。争议不能靠多数票或悄悄修改冻结结果消除；未解决的忠实度争议或关键问题均须延期。

对每个语言×路径、每个对照：

1. `N ≥ 30` 个预注册的独立来源级单元。30 是最低操作门槛，不是功效分析或代表性保证。
2. 一个来源的两次生成×两种展示顺序，共四个判断。四次均胜才计 `W`，均负计 `L`，均平计 `T`；其余有效组合计不稳定 `U`，任何缺失或无效计 `I`。
3. `N = W + L + T + U + I`，不删除平局、不稳定、失败或无效来源。重复次数与裁判观察条数都不增加 `N`。`I > 0` 即延期，仍保留原分母。
4. 净偏好 `(W − L) / N ≥ 0.15`；`L / N ≤ 0.10`；`(U + I) / N ≤ 0.10`。
5. 对稳定胜负作精确单侧符号检验：在 `X ~ Binomial(W + L, 0.5)` 下计算 `P(X ≥ W)`；没有胜负时 `p = 1`。所有预注册语言×路径单元格和两种对照组成同一个检验族，`K = 单元格数 × 2`，每项均须 `p ≤ 0.05 / K`。不得删除未完成或不利单元格缩小 K。
6. 所有候选输出的硬保护检查通过，且没有未解决的失真争议或关键问题。

上述四票一致的规则较保守，但仍无法证明裁判正确；符号检验只处理登记模型下的胜负随机性，不修复抽样偏差、数据泄露、裁判同源性或选题偏差。统计显著也不自动等于实际有用。

## 硬保护、证据与发布复核

发布层级必须逐项提供 `pass/fail/unknown` 及非空证据引用。省略字段、以字符串假扮布尔值、没有检查就填 `pass` 都不可接受。需要检查：许可证、安全、公共数据授权、数量/单位/否定、限定/范围/因果/引用角色、作者立场/优先级/声音、隐私同意、不默认保存私人原文、画像停用与一次性忽略及文件目标边界、公开导出清理、可执行回滚。

文档变更未涉及某项行为时，也不能静默跳过：通过差异检查说明该行为未变，并附证据。行为修复或质量试验则须查看相应实际输出和操作证据。仅回复“不会保存”或提出文件修改，不能证明磁盘没有写入。

评估器只检验报告的完整性、类型、计数和门槛，**不读取或认证引用的原始产物**，不判断语义、不验证授权文件，也不验证人或模型的真实身份。哈希与声明本身不能证明观察发生过。非作者复核者必须实际核对：预注册早于试验、冻结哈希、所有计划单元和原始结果、设置一致性、裁判隔离、许可、预算账本和发布差异。将复核身份、独立性和证据引用记录在 `review`；自填 JSON 不能代替此步骤。

合格的常规更新可由主维护者在既有用户授权内发布，无须重复索要常规批准。发布前运行仓库检查与单元测试，只导出公开白名单文件，记录确切版本、适用结论、限制和回滚点。私密原文、私人样文、真实画像、授权材料和原始私密运行日志永不进入公共仓库；公开报告只能包含获准的汇总和去标识引用。遇到真实回归，停止继续推广，按已核验的备份/提交回滚并说明影响；不得破坏用户修改或悄悄覆盖本地画像。

真实个人声音的有效性需要本人授权样文、语言/文体覆盖和本人实际阅读反馈。仰慕的他人风格与作者自我画像分开；临时使用与持久授权分开；学习结果先为暂定，不能伪造本人认可。上述判断不能完全外包给模型，本评估器不接受“个人声音已验证”这一发布主张。

## 预算、停止条件与分批积累

默认每周最多调查一个候选，筛分不超过 20 分钟；每个日历月全部维护活动合计最多 48 次模型生成/裁判调用，只使用现有可用工具，不购买付费 API 或新订阅。重复、换序、失败调用和重试均计入调用预算，不能每个文件单独重置额度。离线算术和单元测试不算模型调用。更高额度或新增费用须有明确授权记录。

配额耗尽、鉴权失败、429 限流或连续两次传输失败时停止；不得改账号、改支付来源或隐蔽重试绕过限制。不要为了用满预算找变更。没有值得调查的候选时，记录无变更即可。

可以跨周、跨月完成**事先冻结的固定样本计划**：保持候选、对照、提示、来源清单和分析不变，未完成时只能报告 `defer`。不因中途结果好坏调整样本量；不能补到显著、只保留好批次或反复检验择时发布。若条件或模型发生变化，记录原试验未完成并另立方案，不将两套条件混算。月度额度是上限，不是承诺足够完成风格优势验证；独立裁判不可用时保持探索性定位。

## 离线工具与记录格式

在仓库根目录运行：

```sh
python3 -B scripts/assess_update.py examples/update-evidence.json
python3 -B -m unittest discover -s tests -p 'test_assess_update.py'
```

示例是明确标记的虚构数据，预期输出 `reject`，退出码 2。不要把示例的占位符换成 `pass` 就当作实测证据。工具不联网、不调用模型、不修改输入、不安装、不发布；结果输出到标准输出，并记录输入 SHA-256。

| decision | 含义 | 退出码 |
|---|---|---|
| `investigate` | 启发式筛分通过，尚不支持发布 | 1 |
| `defer` | 证据不足、门槛未过或停止条件生效 | 1 |
| `reject` | 格式/主张不受支持、合成示例或明确否决 | 2 |
| `eligible_for_release_review` | 所报告条件满足；仍需核验产物并按授权发布 | 0 |

`automatic_publish` 始终为 `false`。退出码 0 不是“效果被证明”或“发布已获新授权”。

记录根字段必须恰好包含：`schema_version`（整数 1）、`synthetic`（布尔）、`tier`、`candidate`（非空标识）、`claim`、`screening`、`checks`、`review`、`budget`、`evidence`。未知字段、缺失字段、重复 JSON 键、非有限数和错误类型均拒绝。

- `screening`：上表五个键，每项恰好为 `{score: 0|1|2, rationale: 非空文字}`。
- `checks`：筛分仅含 `license/security/public_data_authorization`；三个发布层级须包含脚本 `RELEASE_CHECKS` 的全部键。每项为 `{status: pass|fail|unknown, evidence: 非空引用或说明}`。
- `review`：发布层级为 `{reviewer, independent_of_author, evidence}`；筛分必须为 `null`。独立操作性复核可由另一 agent 完成。
- `budget`：示例列出完整字段。`transport_failures` 记录当前连续传输失败数；收到成功响应后重置。`expansion_authorization` 为 `null` 或明确扩展授权的引用；即使有扩展授权，也不能绕过配额/鉴权/限流/传输失败停止条件。
- `evidence`：筛分为 `null`；发布层级包含 `kind`（只有 `observed` 可支持资格）、`artifacts`（至少一个 `{reference, sha256}`，SHA-256 为 64 位小写十六进制）。文档层级另含 `behavior_unchanged` 与 `structure_checks_passed` 两个布尔值。
- 两个经验层级另含 `protocol` 和 `cells`。`protocol` 必须含脚本对应字段，政策版本固定为 `maintenance-v1`。`reference` 指向冻结预注册；`candidate_sha256/incumbent_sha256` 绑定不同的完整快照。五个通用布尔条件为 `frozen_before_trials/fixed_sample/no_optional_stopping/source_level_units/settings_identical`。风格层级再要求 `fresh_heldout/anonymous/swapped_order/judge_independent`，以及 `judge_type/judge_identity/independence_evidence`。
- `protocol.cells` 每项为 `{language: zh|en, path: human-writing|academic-clarity|combined, source_ids: [...]}`，登记完整分母。`evidence.cells` 每项为 `{language, path, units: [...]}`；不能有重复或未登记来源。缺失计划来源仍进入统计，不会被丢弃。
- 修复的每个 unit 为 `{source_id, role: original|guard, unseen, incumbent_reproduced: [布尔, 布尔], repeats: [观察, 观察]}`。修复观察为 `{result: pass|fail|invalid, candidate_fidelity: pass|fail|unknown, privacy: pass|fail|unknown, fidelity_dispute: 布尔, critical_issue: 布尔}`。
- 风格的每个 unit 为 `{source_id, comparisons: {incumbent: [观察, 观察], plain: [观察, 观察]}}`。风格观察将修复观察的 `result` 换成 `normal` 与 `swapped`，各为 `win|loss|tie|invalid`，其他保护字段相同。这里的胜负均以候选为基准，是去盲映射后的结果，不是匿名 A/B 字母。

缺失的真实观察应使用完整观察槽位并将结果填为 `invalid`，从而计入 `I`。整项计划来源未出现也保留在分母内；但省略必要重复、顺序或保护字段属于格式错误，会直接 `reject`，不输出统计指标。两者都不能获得发布资格。

本工具刻意不接受手填总胜率、调用者自选 K、排除条目或动态阈值。完整字段定义以 [评估器](../scripts/assess_update.py) 为准；[测试](../tests/test_assess_update.py) 中的构造函数是语法与边界示例，不是实际实验记录。工具不自动冻结外部计划、核对账本或防止伪造，独立产物复核是不可省略的第二道关口。

## 当前限制对应的改进路线

| 限制 | 后续所需证据，而非当前已完成事项 |
|---|---|
| 小型开发集且部分胜出存在判定争议 | 先冻结新假设与来源级计划，再收集独立新保留材料；保留争议和失败记录 |
| 同模型生成与裁判 | 独立模型族或独立人类读者，记录隔离、量表和分歧；在此之前不升级为一般优势标签 |
| 回复承诺不能证明文件/画像状态 | 在临时目录中用合成材料验证真实读写、停用、一次性覆盖、忽略、迁移与不保存原文行为 |
| 尚无真实个人风格反馈 | 仅在本人明确授权后使用相应语言/文体样文，学习→审阅→纠正，等待实际反馈，不公开原文 |
| 维护预算有限 | 固定计划分批积累；证据未足保持延期，不为达标调整门槛或消耗新费用 |

方法依据仅支持流程原则：OpenAI 的[评测最佳实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices) 建议采用任务特定评测、明确指标、比较方法及人类反馈校准；[MT-Bench / Chatbot Arena 研究](https://arxiv.org/abs/2306.05685) 讨论模型裁判的位置、篇幅和自我偏好。这不为本仓库的 7 分、12 个、30 个、15% 或 10% 门槛背书。维护者须持续审查这些治理选择，但不得拿正在评估的结果反向选择通过线。
