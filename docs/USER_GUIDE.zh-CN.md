# 中文使用指南

[返回首页](../README.md) · [English guide](USER_GUIDE.en.md) · [评估记录](../EVALUATION.md) · [维护说明](MAINTENANCE.md)

适用于 Human Writing **2.12.1** 与 Academic Clarity **1.1.1**。本项目是功能实验版，不承诺所有文章都会更好，也不承诺 AI 检测器结果。

如果你只想马上试用，读第2节和第3节即可。档案与两个技能组合都不是前置要求。

## 1. 先弄明白：skill 是什么？

这里的 skill（技能）是一份给 AI 助手看的“编辑工作说明”，连同必要参考资料一起放在文件夹里。入口是 `SKILL.md`；助手在适用时读取它，再按照你的任务处理文章。

因此：

- 它不是一个新的语言模型，也没有训练一个“你的分身”。
- 它不是独立写作软件；仍需要能读取技能的客户端和可用模型。
- 它不是事实核查、查重、AI 检测或检测规避工具。
- 安装指令文件不等于购买模型服务，也不保证某个客户端能编辑 Word、PDF 或保存文件。
- 不需要编程才能使用。Python、Node.js 和仓库检查脚本主要供维护者检查包结构，不是普通改写的前置步骤。

### 两个技能分别做什么？

| 技能 | 通俗解释 | 典型场景 |
| --- | --- | --- |
| `human-writing` | 让已有观点按更清楚的顺序展开；先看段落，再看句子和词语，保留作者的重点与口吻 | 中英文论文、课程 essay、评论、个人文章 |
| `academic-clarity` | 分清“这句话确有必要的限制”和“这段只是又辩解了一遍”，只压缩后者 | 论文、研究报告、课程 essay 中反复的免责声明、限定和结果开脱 |

“作者声音”不等于多写“我认为”、加情绪、讲故事或故意变换句长。它可以来自你把哪一点写得更充分、如何推进论证、在哪里保留犹豫。技能不应补出你没有表达过的经历、态度或感受。

“更清楚”也不等于“更肯定”。`可能`、`在本样本中`、`不证明因果`可能保护不同的信息，不能因为多就一并删掉。

## 2. 三分钟上手：安装、识别、试一段

这是最短操作路线，不是耗时保证。首次下载、客户端重启和模型响应可能需要更久。

### 第一步：确认使用环境

准备好：

1. 一个支持技能或能读取完整本地技能目录的 AI 客户端。
2. 该客户端的可用模型访问权限。
3. 一段你有权提供的文字。第一次用不含隐私的短段落即可。

“客户端”就是你与 AI 对话的应用、命令行工具或编辑器扩展，不是这两个技能本身。

下面的安装器与目录说明以 Codex 为例，不是所有聊天产品通用的安装办法。当前官方文档支持项目中的 `.agents/skills` 与用户级技能目录，支持明确选择和按任务匹配技能，并说明了安装后的自动发现与重启回退。详见 [OpenAI Build skills](https://learn.chatgpt.com/docs/build-skills)（核对于 2026-09-18）。

### 第二步：任选一种安装方式

#### 方式 A：让安装器处理，适合初次使用

在提供 `skill-installer` 的 Codex 中发送：

```text
请用 skill-installer 从 GitHub 仓库 vannyben7/writing-skills 安装以下技能：
skills/human-writing
skills/academic-clarity

先检查现有技能。遇到同名目录不要覆盖，报告版本和路径让我选择。
只安装技能所需的完整目录，不安装额外付费工具或服务。
完成后告诉我两个技能的实际安装路径和版本。
```

只装一个也可以。支持技能提及时，可通过选择器选择安装器，或在 Codex CLI / IDE 中写 `$skill-installer`。安装器可能需要访问 GitHub；网络、权限或组织策略阻止安装时，先处理客户端报告的问题，不要靠改写路径猜测解决。

不要假定安装器一定写入某个固定目录。让它报告真实目标，尤其是在旧版本客户端或有自定义配置的环境中。`.codex/skills` 可出现在特定既有环境里，但不是本文对所有客户端的通用默认值。

#### 方式 B：手动复制到写作项目，不覆盖已有目录

先从 [本仓库](https://github.com/vannyben7/writing-skills) 下载并解压，或使用你已有的仓库副本。进入自己的写作项目，把两个完整子目录分别复制成：

```text
你的写作项目/
└── .agents/
    └── skills/
        ├── human-writing/
        │   ├── SKILL.md
        │   └── 其他原有文件和目录
        └── academic-clarity/
            ├── SKILL.md
            └── 其他原有文件和目录
```

必须复制整个 `skills/human-writing` 或 `skills/academic-clarity`，包括隐藏元数据和配套参考；不要只拿走 `SKILL.md`。若目标里已有同名技能，停止，先核对版本与自定义改动。

熟悉 macOS/Linux 终端时，可以在写作项目目录执行以下示例。先把来源路径换成实际位置；它不是可原样使用的下载地址。Windows 用户可用文件管理器完成相同的非覆盖复制，不必照抄 shell 语法。

```bash
writing_skills_source="/path/to/writing-skills"
for skill_name in human-writing academic-clarity; do
  source_dir="$writing_skills_source/skills/$skill_name"
  destination=".agents/skills/$skill_name"
  if [ ! -f "$source_dir/SKILL.md" ]; then
    printf 'Source missing: %s\n' "$source_dir"
  elif [ -e "$destination" ] || [ -L "$destination" ]; then
    printf 'Already exists; not copied: %s\n' "$destination"
  else
    mkdir -p .agents/skills && cp -R "$source_dir" "$destination"
  fi
done
```

确认终端当前所在的确实是目标写作项目，而不是本仓库或其他项目。不要同时运行多个复制操作。这里只展示本项目复制路径；其他客户端应使用它自己的技能目录。

#### 方式 C：先不安装，直接读取

如果客户端能读本地文件，可以将已下载的完整技能目录放在可访问的位置，然后说：

```text
请先读取我提供的 human-writing 目录中的 SKILL.md，
并按任务读取它指向的参考资料，再改写下文。只返回文字，不改文件。
```

你需要真正提供可访问的目录或文件位置。只有技能名称、网页链接或孤立的 `SKILL.md`，不等于客户端已经获得完整规则。若客户端不能读本地文件，请使用它支持的安装/附件机制，不要假定路径文字会自动上传文件。

仓库根没有可直接使用的 Claude marketplace 配置；Human Writing 子目录中保留的 marketplace 仅是该包的本地元数据。Academic Clarity 的可选 Node 安装器也不是写作模型，普通使用无需运行它；本项目不要求从 npm 安装或发布包。

### 第三步：确认识别，然后试短文

可以先问：

```text
你现在能使用 human-writing 和 academic-clarity 吗？
请根据实际可读取的技能文件，报告名称、版本和路径；没有加载就明确说没有。
```

按官方说明，Codex 应自动发现新技能；没有出现时先重启，再核对项目、目录层级和权限。同名技能不会自动合并，应明确选择来源路径。[官方说明](https://learn.chatgpt.com/docs/build-skills)

第一次只交给它一段文字：

```text
用 human-writing 改写下面这段中文课程 essay。
目标：让论点与证据衔接更清楚，保留我的立场和原有事实。
只在回复中给出修订稿，不写入文件，不使用任何风格档案。

[粘贴原文]
```

然后与原文对照。先确认没有丢信息，再决定要不要用于全文。

## 3. 怎么提要求：三种模式

明确“做什么、处理哪里、交付什么”通常比一句“去 AI 味”更容易核对。

### 只审计：指出问题，不改文

适合你还想自己决定怎么写的时候。

```text
用 academic-clarity 只审计下面这两段论文。
指出重复的辩解，并解释哪些样本、因果或来源限定必须保留。
不要整段改写，不要修改文件。没有必要修改的地方可以说保留。

[粘贴原文]
```

Academic Clarity 可能使用这些标签：

| 标签 | 意思 |
| --- | --- |
| `KEEP` | 原文有效，或改动会丢信息 |
| `TIGHTEN` | 缩短重复措辞，保留同样信息 |
| `REFRAME` | 调整顺序或重心，不换论点 |
| `RELOCATE` | 移到明确给出的更合适位置，必要的局部限定仍保留 |
| `CUT` | 只删没有独立信息的重复铺垫 |
| `QUERY` | 含义或依据不清，需要你补充；先保留有疑问的原文 |

这些标签不是分数。看到 `QUERY` 不等于内容已经被判错；没有资料核实也不等于可以删除。

### 在回复中改写：不触碰文件

```text
用 human-writing 改写以下英文个人文章。
保留我的犹豫、幽默和已有细节，不新增感受或经历。
只返回英文修订稿，不加评分，不修改任何文件。

[粘贴原文]
```

未指定翻译时，应在原来的语言和文体中工作。改写不是自动翻译。想得到两个候选版本、逐条解释或对照表时，可以额外说明；默认不必输出一套冗长流程。

### 保存到文件：明确授权与目标

较安全的初次做法是另存修订稿：

```text
用 human-writing 读取 draft.md，
把修改后的全文另存为 draft.revised.md，保留原稿。
如果目标已存在，先停下让我选择，不要覆盖。
只编辑正文，保留 YAML、引用键、公式、代码和链接目标。
完成后简述重要改动和仍未解决的问题。
```

确实想覆盖时，明确说“直接修改哪个文件、哪些部分”。仅说“看看 draft.md”或把路径当原文来源，不等于授权覆盖。

示例中的 YAML 指文件开头可能存在的元数据；引用键、代码和链接目标也不是普通措辞。没有这些内容的纯文本，可以省去相应要求。

客户端没有文件写入权限时，只能提供回复或修改建议。Word 的修订模式、PDF 文本提取、参考文献管理器、图表和版式保存需要相应客户端工具；技能不提供这些转换能力。格式重要的稿件，修改后还要打开文件检查。

### 常用任务模板

```text
技能：human-writing / academic-clarity（选择一个）
文章类型与语言：例如中文课程 essay
动作：只审计 / 回复中改写 / 保存到明确路径
读者与目的：例如供课程导师阅读，解释某个管理观点
允许改动：例如可以重排段落，不增加论点，不改引用
必须保留：数字、专业术语、因果边界、我的明确立场
风格档案：这次不用 / 明确指定路径及是否临时启用
交付：例如只给修订稿，加一条必要的未解决问题说明

原文：
……
```

不必每次填满。简单任务中，动作、原文和不可改动的信息最重要。

## 4. 看得见的例子：改哪里，保留什么？

以下全部是为说明用途写的合成例子，不是评估语料、真实研究、私人样文或实际模型输出。它们展示一种可行编辑，不证明技能必然产生这种结果。

### 例一：Human Writing 让论文观点先出现

原文：

> 本文关注的是排班制度。排班制度是否稳定，会影响员工能否安排照护。访谈中的六位员工提到临时换班。其中四位说，他们因此取消过照护安排。本文认为，评价排班制度不能只看人力成本，还应考虑员工安排生活的能力。

一种改法：

> 评价排班制度不能只看人力成本，还应考虑员工安排生活的能力。制度是否稳定，会影响员工能否安排照护：访谈中的六位员工提到临时换班，其中四位说，他们因此取消过照护安排。

变化是把原本已有的论点提前，把同一组访谈说明连起来。“六位”“其中四位”和“说”都保留：这仍是受访者的陈述，不是助手独立核实的事实。没有添加新的员工故事或管理主张。

### 例二：Academic Clarity 压缩铺垫，不压掉限制

原文：

> 需要强调的是，本研究仅纳入两所城市学校的48名学生，因此结果不能代表其他学校。值得注意的是，参与次数与结课成绩存在相关关系，但这一相关关系并不证明因果关系。

一种改法：

> 本研究仅纳入两所城市学校的48名学生，因此结果不能代表其他学校。参与次数与结课成绩相关，但这不证明因果关系。

假设两处引导语在上下文中只是重复铺垫，删除它们没有增加或减少研究结论。样本范围、人数、代表性限制和因果限制仍然在原处。不能改成“参与能够提高成绩”。

### 例三：必要限定多，也可以不改

英文原文：

> Among the 24 respondents who completed both surveys, reported confidence increased. The convenience sample does not represent all students, and the before–after comparison does not identify a causal effect.

合理结果可以是 `KEEP`。24名、两次都完成、报告的信心、非代表性样本、不能识别因果效应，各自保护不同的信息。不能以“限定太多”为由删成“Students became more confident because of the course.”

### 怎么核对任何一次修改？

重点看：

1. 数字、单位、时间、范围和“超过/至少”等量词是否保留。
2. “没有”“未发现”“不代表”等否定是否保留。
3. 相关是否被写成因果，计划是否被写成已经实施，自报是否被写成客观测量。
4. “可能”“观察到”“作者认为”等证据强度是否变化。
5. 引文仍然支持同一主张吗？反驳来源有没有被变成赞同来源？
6. 你的实质立场、信念、感受、反讽与不确定性有没有被抹掉或新增。
7. 只调整表达，还是已经换了论点？若你授权了后者，应明确承认是实质修改。

长篇建议按完整论证单元处理，而不是孤立一句句“降重”。给出必要的前后文；最后再通读全文，防止各段对同一结论使用不同强度。

## 5. 可选风格档案：用之前先知道边界

风格档案记录“这份材料怎样组织表达”，例如先给具体观察、再提出判断，或让关键反例占更多篇幅。它不记录“这个人是什么性格”，不授权推断身份、经历或信念。

你可以完全不用档案。也可以提供一段样文只指导本次改写，不保存任何档案。

### 从样文开始，不把暂定观察当成熟模型

```text
用 human-writing 学习下面三段我自己写的中文课程 essay。
先展示暂定的表达偏好、证据所在的样本与段落、尚不确定的部分。
用我接着提供的一小段草稿做校准，不要读取其他文件。
本次只在回复中展示，不保存样文或档案。
```

如果确实需要保存，再单独明确：

```text
请把我确认的暂定档案保存到写作项目的 writing-profiles/course.md。
不要放进共享技能目录；文件已存在时先让我选择。
证据只保存概述与样本定位，不保存原文、私人事实或姓名。
尚未得到我反馈的校准结果，不要标为已验证。
```

档案以 Markdown 或 JSON 保存，都可以手动查看和纠正。通常包含通用偏好、不同语言、不同文体以及语言与文体交叉层的观察，并区分“暂定”和“稳定”。一个明确说出的偏好可以被记录为偏好，但不是长期写作习惯的实证证明。

中文样文不能建立英文句法偏好；课程 essay 的表达习惯也不必套到个人随笔。少量样文先小范围试用，收到真实反馈后再修正，而不是从一次输出宣称“已经完全像你”。

### 自己的文章与欣赏的文章分开

```text
下面是我欣赏的第三方文章，不是我的作品。
只学习它组织证据和反例的方式，记录为 target-style。
不要把其中的私人经历、观点、比喻或原句写进我的文章。
```

`self` 表示自己的作品，`target-style` 表示欣赏的风格目标，`synthetic-test` 表示合成材料。翻译、他人重写或来源不明的文本需要注明，不能直接当作稳定的自写证据。模型改过的文章也不会自动成为你的自写样本。

### 选用、停用与临时忽略

下列“档案”都指明确的文件，而不是让助手猜测最近使用过哪个。

| 想做的事 | 可以这样说 | 应发生的事 |
| --- | --- | --- |
| 本次应用已启用档案 | “按 writing-profiles/course.md 改写本段，不修改档案” | 读取状态，只用适用的语言与文体层 |
| 查看 | “展示这个档案的偏好、证据和限制，不应用它” | 只查看，不改状态 |
| 纠正或补充 | “把这个观察改为……，其他部分不动” | 只改指定观察，记录你的纠正 |
| 本次换一个 | “这次改用指定的另一份档案” | 本次选择；不默认合并或持久保存 |
| 停用 | “停用这个档案，保留文件” | `enabled: false`；有指向它的已保存默认选择时清除该关联 |
| 临时使用停用档案 | “它虽然停用了，但这次明确使用，不修改保存状态” | 本次允许使用，下次不因此启用 |
| 临时不用任何档案 | “这次不用档案” | 本次不读取、不应用、不查询选择器，也不改保存状态 |
| 重新启用 | “重新启用这个档案，但不要设成默认” | 改这个档案的启用状态，不额外建立默认选择 |
| 保存默认选择 | “明确把这份档案设为以后默认，告诉我选择记录保存在哪” | 只在这个明确请求下保存默认选择；启用状态仍需另行明确 |
| 删除 | “删除这个确切档案，不删除样文或其他档案” | 只处理指定文件及失效关联；说明可否恢复 |

仅说出一个 `enabled: false` 档案的名称，不等于让它启用。普通改写可以继续，不应假装已经按停用档案匹配风格。

本版本对“明确要求以已有细节表达克制感受”的档案任务有一条专项规则：允许压缩原文细节与自身限定支撑不了的修辞性拔高，不只换成同样宏大的近义表达。但真实立场、独立的信念或情绪、具体事件和不确定性仍需保留；不是所有宏大判断都应删。

### 隐私要分两层看

技能规则要求：只用你授权的材料；默认保存证据概述与定位；保留原文片段需明确许可；不扫描私人文件夹来寻找更多样文。

客户端与模型服务如何传输、保存和使用文字，是另一层问题。档案存在本地不代表推理也在本地；“不保存样文”的编辑要求不能替代服务商的数据政策。先脱敏，确认你有权提供未发表论文、同学作业、客户材料或第三方文章。

真实档案与样文不要放入本公共仓库、技能包或公开提交。迁移档案时，也要检查其中的定位、文件路径和保留片段是否包含隐私。公开的 [TEST 示例](../skills/human-writing/assets/TEST-profile.json) 只是默认停用的合成格式示范，不是可以直接冒充你的档案。

档案协议详见 [Human Writing 规则](../skills/human-writing/references/style-profiles.md)及 [Academic Clarity 兼容说明](../skills/academic-clarity/references/voice-and-composition.md)。这些是指令约定，不是能够强制拦截所有错误的权限系统；重要的文件状态应实际检查。

<a id="combine"></a>

## 6. 两个技能怎样组合？

只有你确实需要学术限定清理和行文调整时，才组合。个人文章通常只用 Human Writing。

```text
对下面的论文段落做一次组合编辑：
先用 academic-clarity 清理重复的防御性铺垫，
再用 human-writing 调整段落与句子衔接。
第二步保留第一步列出的科学边界和未解决问题，并同时读原文。
最后只与最初原文核对一次语义，给我最终文本和必要的疑问说明。
不要自动循环，不使用风格档案，不修改文件。
```

流程是：原文 → Academic Clarity → Human Writing → 对照原文。

交接可以短到一句：“保留样本范围、仅相关非因果、自报状态；来源尚未核实。”复杂文本可以列出保护的主张、原样保留的片段、引文作用、允许的改动和未解决问题，不必另建文件。

第二步的中间稿漏了某条信息，并不意味着原文那条信息已经得到删除授权。无法确认的主张不能被顺手写成事实。更多细节见[交接契约](../skills/human-writing/references/composition-contract.md)。

## 7. 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 安装后找不到技能 | 是否在正确项目？文件夹是否直接包含 `SKILL.md`？是否复制了完整目录？重启客户端后再看；确认客户端确实支持这一发现机制 |
| 出现两个同名技能 | 核对来源和实际路径，明确选一个；备份不要留在自动扫描目录中；不要以为它们会合并 |
| 只写了名称，结果像普通改写 | 要求报告实际读取的技能路径与版本；不能读取资源的客户端不会凭空拥有规则 |
| 自动用了不想用的技能 | 本次明确指定所需任务和技能；若要长期停用，使用客户端自己的技能管理机制，区别于停用风格档案 |
| 改动太多、过于口语化 | 限定文体、允许的范围，先要求审计；指出要保留的原句与术语，而非继续追求“更像人” |
| 事实或引用被改了 | 保留原稿，指出具体差异并要求恢复；若原文含义不清，先答复 `QUERY`；不要把流畅度当忠实度 |
| 提示档案停用 | 如果只想这次用，要明确临时授权；若本次不用，明确说“不加载任何档案” |
| 想保存文件，却只返回文本 | 核实客户端写入权限与目标格式支持；明确指定输出路径，不能靠技能声明获得系统权限 |
| 想直接改 Word/PDF 或保留修订痕迹 | 使用具备相关文档工具的客户端，备份原文件，明确格式和修订要求；本技能不是转换器 |
| 网络错误、超时或额度不足 | 这是下载或模型服务层问题；检查客户端状态、输出是否已完成，不要反复全篇重跑造成重复工作或额外费用 |
| 输出和示例不同 | 示例不是固定答案；核对实际任务、输入、模型和版本。优先检查信息是否保留，而不是是否使用同样句式 |
| 评分或“AI 率”没变 | 本项目没有检测器目标，不以某个分数为验收条件 |

## 8. 版本、备份、迁移与回退

当前版本以每个技能 `SKILL.md` 的 `metadata.version` 为准。文档中的“候选”字样在部分入口仍作为已评估版本的来源记录保留；公开分发定位是功能实验版，不是上游官方更新。

一次安全更新可以这样安排：

1. 记录正在使用的技能路径、版本、来源提交，以及你自己的修改。
2. 备份整个旧技能目录，放在客户端技能扫描范围之外；私人档案另外备份。
3. 下载新版本到独立位置，阅读变更记录与[评估记录](../EVALUATION.md)。
4. 不直接覆盖同名目录。确认更新范围后，将旧目录移出发现位置，再放入新完整目录；每一步都检查实际目标。
5. 让客户端重新发现并报告实际版本，用不含隐私的小段落检查行为。
6. 需要回退时，先移出新目录，再恢复完整旧目录并确认版本。不必删除样文、文章或档案。

这描述的是人工可核对的步骤，不是仓库已提供一个自动回滚命令。普通复制安装不会随着 `git pull` 自动更新；如果你另行配置了链接或其他管理工具，则应按其实际行为检查。

从旧名 `humanizer` 或 `academic-defensive-writing-auditor` 迁移时，先确认旧版本和实际位置，保留自定义改动，再更新自己的调用名称或工作流引用。新版本不是简单换名后一定兼容所有旧习惯。不要擅自删除旧技能；避免两个副本同时被模糊调用。

两个当前技能可以使用同一种便携档案，但不能承诺任何第三方旧档案都会自动迁移。迁移先复制备份，再核对来源类别、语言与文体层、启用状态、默认选择、样本定位和隐私片段。应用档案不等于授权改档案。

具体维护和发布流程见 [MAINTENANCE.md](MAINTENANCE.md)。本指南不会要求你安装定时任务、付费服务或自动更新工具。

## 10. 证据边界：可以期待什么，不能期待什么？

当前证据支持的是有限场景的功能试用，不是普遍写作优势。完整数字见 [EVALUATION.md](../EVALUATION.md)。

- 一般改写试验：8份来源文本、15个文本与路径组合、45份输出、60条有效裁判观察。多数为平局；部分胜出有事后判定争议。
- 修复前合成工作流：11/12通过。剩余问题是克制文风没有充分落实，不是据此判定所有档案控制失败。
- 档案专项定向回归：Human Writing 2.12.1为5/5，2.12.0对照为4/5。集合包含已知失败与定向保护案例，不是广泛随机盲测。
- 评估记录中的36项是历史写作评估工具链的离线测试，不是36篇写作测试，也不是当前仓库的测试总数。根结构检查还运行使用模拟数据的维护工具单元测试，应与该历史数字分开计算。模型裁判、结构测试与读者认可不能互相替代。
- 没有保留集泛化结果、真实私人档案或真实持久状态读写验证，也没有用户校准认可、检测规避或个人风格相似度结论。

一般改写阶段测试的是 Human Writing 2.12.0 和 Academic Clarity 1.1.1；2.12.1 的普通入口正文未变，档案参考中的变化由专项回归单独检查。不要把不同版本、阶段或观察单位混成一个总通过率。

提交课程作业或论文时，仍应遵守所在机构关于 AI 辅助和作者责任的要求。你需要自己核查引用、论证和事实；不要把编辑技能当作事实证明或学术诚信保证。
